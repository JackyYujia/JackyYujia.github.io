GPU Benchmark 不只是跑一个数字

2026.08.10GPU / CUDA7 min read

一个 Benchmark 数字只有放回硬件、数据类型、编译参数和测试方法里，才有比较意义。否则它更像一个脱离上下文的成绩单。

先确认测试对象

GEMM 的输入输出类型、矩阵形状、布局和 batch 方式都会改变结果。INT8、FP8、FP16、TF32 与 FP32 对 Tensor Core、累加精度和内存访问的要求并不相同。

CUTLASS 的工程价值

CUTLASS 让 kernel 的 tile、warp、pipeline 和 epilogue 变成可以显式调整的构件。它不保证每次都比库函数快，但它能让性能差异有机会被解释。

shape      = M x N x K
datatype   = FP16 / FP8 / INT8
layout     = row-major / column-major
metric     = TFLOPS + latency + stability

比较时不能忽略硬件代际

同一个配置在 Ada Lovelace、Hopper 或其他加速器上可能触发完全不同的路径。比较时要同时记录硬件型号、时钟、驱动、编译器和 warm-up 策略。

一个更可靠的结论

我更愿意把结论写成“在给定形状、数据类型和硬件环境下，这个实现的瓶颈在哪里”，而不是简单说“更快”。这也是 GPU Benchmark 从 demo 走向工程工具的分界线。
